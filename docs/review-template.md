## 二、Review 检查项

### 1. 是否只写 What，不写 How

检查 PRD 是否只描述用户问题、产品目标、功能范围和验收标准。

不能出现：

- 技术实现方案
- Redis、数据库、接口、代码
- 内部字段名
- “接口返回 200”这类技术指标

结论：通过 / 需修改

```

- 用户是谁
- 用户遇到了什么问题

### 4. 验收标准是否用户可感知

验收标准应该描述用户能看到、能完成、能理解的结果。

好的写法：

- 用户可以在 3 秒内看到成功提示
- 操作失败时，用户可以看到明确失败原因
- 用户无需重复输入即可完成配置

不好的写法：

- 接口返回 200
- 数据写入成功
- 新增某个字段

结论：通过 / 需修改

```
